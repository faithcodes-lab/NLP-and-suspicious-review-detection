## Summary of Discussion

### 1. Sentiment Modelling Progress
The team presented progress on sentiment analysis modelling.

*Key points:*
- Multiple models were implemented to understand performance differences.
- Models were trained using the same dataset for fair comparison.
- Sentiment classification was treated as a *binary problem*:
  - Positive (≥ 4 stars)
  - Negative (≤ 2 stars)
- Neutral reviews were excluded to reduce ambiguity.

The supervisor noted that sentiment classification is relatively straightforward compared to suspicious review detection.

---

### 2. Preprocessing and Reproducibility
To ensure consistency across all models:
- A *shared preprocessing pipeline* was created.
- Cleaned data was saved using *Joblib*.
- All team members used the same processed dataset.

This approach ensured:
- Fair model comparison
- Reproducibility across experiments

---

### 3. Models Implemented
The following models were developed and tested:

- Logistic Regression (baseline model)
- Support Vector Machine (SVM)
- Naive Bayes
- Random Forest
- BERT (transformer-based model)

Each model was evaluated using:
- TF-IDF features (text-only)
- TF-IDF + metadata features (experimental)

---

### 4. Feature Engineering Approach
The team experimented with combining:
- *Text features (TF-IDF)*
- *Metadata features*, including:
  - Review length
  - Verified purchase
  - Helpfulness votes

*Objective:*
To determine whether metadata improves sentiment classification performance.

*Findings:*
- Metadata did not consistently improve model performance
- In some cases, it reduced accuracy

---

### 5. Handling Imbalanced Dataset
The dataset contained significantly more positive reviews than negative ones.

*Issues observed:*
- Models biased toward predicting positive reviews
- Misclassification of negative reviews

*Solution:*
- Applied *class weighting (balanced weights)*

*Outcome:*
- Improved classification of minority class
- Reduced bias, though not completely eliminated

---

### 6. Model Performance and Evaluation
The team discussed evaluation metrics.

*Key points:*
- Accuracy alone was not reliable due to class imbalance
- Greater focus placed on:
  - *F1 Score*
  - Precision and Recall

*Performance insights:*
- *BERT achieved the best overall performance (highest F1 score)*
- Naive Bayes performed well in accuracy but lacked contextual understanding
- Random Forest achieved ~86% accuracy but underperformed compared to others
- SVM showed stable performance but limited improvement with metadata

---

### 7. Individual Contributions and Challenges

#### Random Forest
- Accuracy: ~86%
- *Challenges:*
  - Long training time
  - Difficulty integrating metadata
  - Initial over-parameterisation slowed execution

---

#### SVM
- Tested both:
  - Text-only features
  - Text + metadata

*Findings:*
- Metadata provided limited improvement
- Some performance decline observed

---

#### BERT
- Strong contextual learning capability
- Accuracy range: ~0.83–0.89

*Challenges:*
- High computational cost
- Training initially took up to 12 hours

*Optimisation:*
- Reduced training time to ~5 hours using lighter configurations

*Limitation:*
- Performance dependent on hardware (GPU vs CPU)

---

### 8. Computational Constraints
The team discussed limitations related to:
- Large dataset size
- Long training times (especially for BERT)
- Hardware limitations (lack of GPU acceleration)

*Supervisor recommendation:*
- Use *sampling strategies*
- Standardise sample size across all team members

---

### 9. Dataset Sampling and Limitations
The team used a *subset of top 30 products* for analysis.

*Limitations:*
- Potential loss of hidden patterns from excluded data
- Reduced generalisability of results

*Supervisor feedback:*
- Sampling is acceptable but should be:
  - Consistent across team members
  - Clearly documented as a limitation

---

### 10. Misclassification Analysis
The supervisor suggested analysing:
- Misclassified samples (~10%)

*Purpose:*
- Identify weaknesses in the model
- Improve feature engineering
- Detect unusual patterns (e.g., mismatched sentiment vs rating)

---

### 11. Model Explainability
The importance of explainability was emphasised.

*Planned approach:*
- Implement *SHAP (SHapley Additive Explanations)*

*Objective:*
- Understand:
  - Which features influence predictions
  - Why certain reviews are classified as positive or negative

*Additional idea:*
- Analyse word importance in reviews (feature-level insights)

---

### 12. Transition to Suspicious Review Detection
The team outlined the next phase of the project.

*Planned approach:*
- Use sentiment analysis outputs as input features
- Combine:
  - Text features
  - Metadata features
  - Behavioural patterns

---

### 13. Suspicious Review Features
Proposed features include:
- Verified purchase status
- Review length (very short reviews)
- Burst activity (multiple reviews in short time)
- Extreme rating vs sentiment mismatch
- Generic/promotional language
- AI-generated probability score

*Discussion:*
- AI score will be used as a *probabilistic feature*, not a definitive label
- Limitations of AI detection will be clearly documented

---

### 14. Modelling Plan for Next Phase
*Models to be used:*
- Logistic Regression
- SVM
- BERT

*Approach:*
- Hybrid model combining text + metadata
- Focus on fewer models for efficiency and depth

---

### 15. Key Decisions
- Use *BERT as the primary model* for sentiment prediction
- Apply the model to the full dataset
- Avoid deploying all models for final prediction
- Standardise preprocessing and sampling
- Incorporate explainability into final output
