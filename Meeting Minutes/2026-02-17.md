## Summary of Discussion

### 1. Collaboration on Data Cleaning and EDA
- The team discussed challenges of working simultaneously on the same dataset while performing different tasks (EDA, cleaning, preprocessing).
- Concerns were raised about inconsistencies if different members clean the dataset separately, which could produce different results and affect later analysis.
- It was agreed that:
  - Data cleaning should be done using **one shared script** to ensure consistency.
  - EDA tasks can be divided across team members once the cleaned dataset is standardized.
- Members suggested splitting responsibilities such as:
  - Missing value checks  
  - Statistical summaries  
  - Understanding dataset structure  
  - User counts, rating distributions, and post characteristics  

---

### 2. Managing Shared Files and Scripts
- The team discussed working on different files versus the same file.
- Key points:
  - Working on different analysis scripts is acceptable.
  - Cleaning scripts must remain unified to avoid producing conflicting datasets.
  - Common preprocessing (“data munging”) scripts should be created and reused by everyone before analysis.

---

### 3. Version Control for Team Collaboration
- Version control tools were introduced as the main solution for collaboration conflicts.
- The team discussed using GitLab (and alternatives like GitHub) to:
  - Share code  
  - Track changes  
  - Merge contributions  
  - Maintain a single codebase  
- Concepts mentioned:
  - Cloning repositories to local machines  
  - Comitting and pushing changes  
  - Pulling updates from teammates  
  - Merge conflicts when multiple people edit the same file  
- It was noted that learning version control is valuable for industry practice but should not slow project progress.

### 6. Dataset Sharing Challenges
- The team discussed difficulties in sharing the large dataset across members.
- A conversation with the supervisor highlighted that:
  - The dataset is static and not regularly updated.
  - Cloud storage services with sufficient capacity may incur costs.
  - Uploading and transferring large files repeatedly would be inefficient.
- Based on this, it was agreed that:
  - Each member will store a local copy of the dataset on their own machine.
  - The dataset will be shared directly among team members through onedrive link.
  - Work will be performed locally to avoid cloud storage limitations and costs.
- This approach was considered practical given the dataset size and project timeline.
