## 1. Pre-processing Notebook and Data Structure

The team was introduced to the pre-processing notebook, which already contains the core preparation steps required for the project. These steps include:
- Data cleaning and preprocessing
- Train-test split
- Preparation of datasets required for model training

The processed datasets have been saved in a shared folder that will be used across the project.

Team members were advised that when implementing their assigned models, they should load the prepared datasets from this shared folder instead of repeating the preprocessing steps.

---

## 2. Shared Folder Structure and Reproducibility

It was explained that the shared folder must be located in the same directory as the scripts/notebooks in order for the data loading process to work correctly.

A demonstration was conducted showing two scenarios:
	1.	When the shared folder was not placed in the same location as the script, the notebook returned an error and the code could not run.
	2.	When the shared folder was placed in the correct location, the notebook executed successfully and the datasets loaded properly.

The purpose of this structure is to ensure reproducibility. Any user who downloads the repository should be able to run the scripts successfully, provided that they download the shared folder and place it in the correct location alongside the notebooks.

---

## 3. Use of Previous Notebooks

Team members were informed that they can refer to previously completed notebooks in the portfolio as a guide for formatting and structuring their work.

However, this does not limit team members from conducting additional research on the model assigned to them in order to better understand or improve their implementation.

## 4. Documentation in Notebooks

It was agreed that every notebook submission must include:
- Markdown cells explaining the code
- Clear explanations of the methodology and results
- References to any materials, papers, or resources used during the development process

This ensures that each notebook clearly communicates both the technical implementation and the reasoning behind it.

---

## 5. Literature Review Documentation

Any research conducted individually during the course of the project should be documented in the literature_review.md file on GitLab.

If a team member reviews a research paper, article, or other relevant material, it should be added to this file so that all references used in the project are centrally documented.
